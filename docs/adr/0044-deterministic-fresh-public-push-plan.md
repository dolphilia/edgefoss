# ADR-0044: Derive a deterministic fresh public push plan from a verified bundle

- Status: Accepted for P5b1a local implementation
- Date: 2026-08-26
- Owners: local storage, sync protocol, and cloud authority leads
- Decision deadline: complete
- Supersedes: none
- Superseded by: none

## Context

P5b0 gives a local client one coherent authority snapshot, but it does not turn
a portable bundle into safe mutations. A correct push must upload blobs before
referencing artifacts, publish nested trees in dependency order, advance change
refs in history order, and reuse operation IDs after an uncertain response.

Incremental and concurrent push introduce a separate ancestry/conflict problem.
The smallest cross-runtime proof is therefore a fresh public authority whose
preflight says every bundled object is missing.

## Decision

Define `edgefossil-public-push-fresh-v0` in
[`push-v0`](../../spec/push-v0.md). The Rust SQLite crate fully verifies a
complete public bundle and the exact fresh P5b0 snapshot, then produces:

- blob steps in manifest order, before artifact steps;
- genesis first;
- trees in child-before-parent topological order;
- changes oldest-first with public `heads/main` expected generations 0..n;
- exact artifact, signature, and blob paths from the verified bundle;
- domain-separated SHA-256 operation IDs shaped as lowercase UUID text.

The plan is limited to 256 artifacts and 256 blobs. Snapshot project/ref must
be null, accepted sequence and policy epoch must be zero, and missing
inventories must exactly equal the bundle. The committed shared vector is
regenerated by TypeScript, independently reproduced by Rust, and executed
against RepositoryDO in the Workers runtime.

## Alternatives considered

- Random operation IDs at execution time: rejected because a process crash
  before persisting the ID can turn response-loss retry into a new mutation.
- Publish in manifest ID order: rejected because lexical IDs do not preserve
  tree or change dependencies.
- Support existing remote heads in the first planner: deferred to P5b1b because
  ancestry, already-accepted changes, ref generations, and conflict outcomes
  need their own contract.
- Add an HTTP push adapter now: deferred until the local cross-runtime mutation
  contract is stable.

## Consequences

- the same verified inputs always yield the same mutation and operation IDs;
- a fresh retry converges through existing P4 upload/publish deduplication;
- no signing key or owner token is placed in the vector or plan;
- operation IDs are public idempotency identifiers, not credentials;
- a failed publish may leave a finalized unreachable blob, but cannot expose an
  artifact because publication still validates all references transactionally;
- bundles larger than the P5b0 preflight bounds require future paging;
- existing/incremental authority state remains unsupported rather than guessed.

## Verification

- TypeScript regenerates the exact bundle and `fresh_push_plan` vector;
- Rust verifies the bundle and reproduces every path, order, ref generation,
  byte size, and operation ID;
- Rust rejects nonfresh and incomplete preflight snapshots;
- Workers runtime executes every step and exact retry;
- final preflight reports no missing IDs, sequence 3, policy epoch 0, and public
  head generation 1 at the vector change;
- schema, routes, bindings, credentials, R2/Queue configuration, staging, and
  production remain unchanged.
