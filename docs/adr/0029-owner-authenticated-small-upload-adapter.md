# ADR-0029: Require owner authentication before exposing small uploads

- Status: Accepted for P4b
- Date: 2026-08-25
- Owners: cloud lead
- Decision deadline: complete
- Supersedes: none
- Superseded by: none

## Context

ADR-0028 implemented upload declaration and finalization as typed internal
`RepositoryDO` RPC. The schema 1 to 2 staging migration is now verified, but
the deployed Worker still has no authenticated mutation surface. P4b needs one
real synthetic R2 write before P4c artifact publishing begins. An
unauthenticated route, a token in source control, or a token accepted through a
URL would make that gate unsafe.

## Decision

Expose the bounded small-upload state machine only through owner-authenticated
HTTP routes:

```text
POST /api/v0/uploads
PUT  /api/v0/uploads/{upload_id}/content
GET  /api/v0/uploads/{upload_id}
POST /api/v0/uploads/{upload_id}/finalize
```

- Staging and production declare `EDGEFOSS_OWNER_TOKEN` as a required Wrangler
  secret. The value is never stored in configuration, source, arguments, URL,
  logs, or completion evidence.
- A local command generates a prefixed token containing 256 random bits. The
  account owner saves it in a password manager and configures it directly as a
  Worker secret.
- Every upload route requires an exact Bearer header. The Worker hashes both
  supplied and expected values before `crypto.subtle.timingSafeEqual`; missing
  or malformed deployed configuration fails closed.
- The fixed bootstrap principal is `owner`. Upload rows advance to application
  schema 3 and store `principal_id`; declaration reuse includes the principal,
  and status, staging, and finalize RPC calls re-check it.
- JSON declarations are limited to 16 KiB. Content is streamed into bounded
  chunks and rejected above the existing 16 MiB small-object limit even if a
  client omits or lies about `Content-Length`.
- Staging verifies size and SHA-256, uses a checksum plus conditional
  create-only R2 write, and verifies an existing object after a retry race.
  Finalization repeats the R2 verification before accepting the final blob.
- Responses use structured errors and `Cache-Control: no-store`. The routes do
  not enable browser CORS and do not expose a public blob read endpoint.

The owner secret is a narrow bootstrap mechanism, not the final multi-user
credential model. P4c will store revocable scoped token hashes and current ACL
state in the authority before member writes are enabled.

## Alternatives considered

- Keep using direct internal RPC only: rejected because it cannot establish
  remote Worker-to-DO-to-R2 evidence.
- Open a temporary unauthenticated smoke route: rejected because a temporary
  public mutation surface is still a vulnerability.
- Put the token in `vars` or GitHub workflow arguments: rejected because those
  surfaces are not secret storage and can leak through source or logs.
- Add Cloudflare Access now: deferred because EdgeFossil must test its own
  authority authentication and the current API is CLI-oriented, not browser
  login.

## Consequences

The next deployment requires one new account-owner action: create and retain
the EdgeFossil owner token, then configure the required staging secret. The
first code deployment migrates RepositoryDO schema 2 to 3. After health reports
schema 3, the reviewed smoke command writes one harmless, deterministic public
test blob and proves declaration, content, and finalize retries converge. It
does not add a Queue consumer or production resource.

## Verification

- invalid or absent bearer authentication returns `401` without mutation;
- the configured secret is generated by Wrangler types and absent from source;
- schema 2 migrates to 3 and existing upload rows become owned by `owner`;
- authenticated declaration, bounded staging, status, and finalize work in the
  Workers runtime;
- staging and finalize retries return one upload and one final key;
- the smoke command accepts the token only through
  `EDGEFOSS_OWNER_TOKEN`, emits no token, and accepts only the approved staging
  Worker origin;
- staging deploy health reports schema 3 before the remote write smoke runs.
